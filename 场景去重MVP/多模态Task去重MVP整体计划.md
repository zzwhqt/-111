# 多模态 Task 去重 MVP 整体计划

更新时间：2026-08-29

## 1. 目标与业务口径

系统接收一个已经按帧范围切分好的 Task 视频片段，在资产库中检索相关 Task，并输出：

- `重复`：主要任务意图与核心动作基本相同，没有有业务意义的新动作阶段。
- `相似`：双方存在明确动作交集，但一方包含额外动作阶段，或只形成子集/超集关系。
- `新数据`：核心动作或任务意图不同；即使场景相同，也不能判重复。
- `无法判断/坏数据`：视频、位姿或描述质量不足。

场景、动作、文本都输出独立证据；最终模块负责按业务口径融合，任何一个子模块的相似度都不直接等于 Task 重复概率。

## 2. 系统模块

### 2.1 场景相似模块

输入：Task RGB 视频帧。

首版：均匀抽取 8 帧，经 OpenCLIP ViT-B/32 编码；Task 向量用于 Faiss 召回，8×8 帧间相似矩阵用于双向帧覆盖重排。

输出：

- `scene_similarity`
- `scene_query_coverage`
- `scene_reference_coverage`
- `scene_quality`
- Top-K 候选与场景证据

优化方向：人物/手部前景抑制、背景区域编码、时段/视角鲁棒抽帧、困难负例训练、基于人工场景等级的概率校准。

### 2.2 动作相似模块

输入：手部 21 关节轨迹、手部末端位姿、头部 6DoF 轨迹和有效帧质量指标。

首版：坐标归一化后提取速度、方向、关节相对结构和动作阶段序列，先用时序距离或学习到的时序编码做候选召回，再用 DTW/局部序列匹配计算双向覆盖。

输出：

- `motion_similarity`
- `motion_query_covered_by_reference`
- `motion_reference_covered_by_query`
- `motion_quality`
- 匹配到的动作时间段

手部位姿是主要动作证据；头部轨迹只辅助表达行走、弯腰、转身和相机运动。双向覆盖用于区分完全重复与子集/超集。

### 2.3 文本语义模块

输入：OSS 中已有的 `scene + task_name + details`，并保留描述来源和版本。

首版：使用统一文本编码器做语义召回，并对动作、对象、工具、目的和动作阶段做结构化抽取。

输出：

- `text_similarity`
- `text_query_covered_by_reference`
- `text_reference_covered_by_query`
- `description_quality`
- 结构化动作/对象/工具证据

需要单独检查“文本与视频是否一致”，避免两段错误描述彼此相似时形成假重复。

### 2.4 最终融合模块

输入：三个子模块的相似度、双向覆盖、质量、时长比例及缺失标记。

第一版使用可解释的动作门控规则：

- 动作和任务意图相同：即使场景不同，也可判重复。
- 只有单向动作覆盖：判相似。
- 动作和任务意图不同：即使场景相同，也判新。
- 位姿或文本质量不足：降低对应证据权重，不把缺失值当低相似。

有足够标注后使用 Logistic Regression 作为可解释基线，再对比 LightGBM；通过校准集做 Platt/Isotonic 概率校准，最终输出 `P(重复)、P(相似)、P(新)` 和可追溯证据。

## 3. 统一母测试集与四轮盲标

评测单位固定为 `query_task_id + reference_task_id = pair_id`。四轮使用完全相同的 Pair 和数据切分，只改变标注时可见的信息。

### 3.1 场景轮

只显示 RGB 视频，不显示 Task 描述、模型分数和动作结论。每对标记：

- `3`：几乎同一物理场景/同一工位
- `2`：工位、设备与布局明显相似
- `1`：同类环境，但不是相似工位
- `0`：环境明显不同
- `9`：画面质量不足，无法判断

### 3.2 动作轮

只显示位姿回放，隐藏 RGB 和文本。标记动作关系：不同、少量交集、查询包含库、库包含查询、基本相同、无法判断；同时标双向覆盖率 `0/25/50/75/100` 和位姿质量。

### 3.3 文本轮

只显示已有描述，隐藏 RGB、位姿和模型分数。标记语义关系、双向语义覆盖率和文本可用性。

### 3.4 整体轮

显示完整 Task 视频及描述，按最终业务口径标记重复、相似、新、坏数据/无法判断，并允许同一查询拥有多个有效参考项。额外记录描述与视频是否一致和理由码。

## 4. 当前四小时场景先导集

### 4.1 数据规模

- 母池：现有 2000 个已完成视觉/文本编码的 Task。
- 参考资产库：100 个 Task。
- 查询：120 个 Task。
- 每个查询：5 个固定参考候选。
- Pair 总数：600。
- 当前只标场景轮；后续动作、文本、整体轮复用相同 600 个 `pair_id`。

页面按一个查询同时完成 5 个候选设计。目标速度为每个查询不超过 2 分钟，120 个查询约 4 小时；支持中断续标、撤销和进度保存。

### 4.2 抽样与候选池

100 个参考资产通过视觉向量球面 KMeans 选取，并限制同一源视频不重复占据参考位。

120 个查询按照相对参考库的“最大视觉相似排名”和“最大文本相似排名”分为四个各 30 条的象限：

1. 高视觉、高文本：容易重复或高度相似。
2. 高视觉、低文本：同场景不同任务的困难负例。
3. 低视觉、高文本：异场景同任务的业务关键样本。
4. 低视觉、低文本：明显负例与基础校验样本。

每个查询的 5 个候选固定为：视觉 Top-2、文本 Top-2、一个确定性随机负例；候选重复时按后续排名补足。模型排名和分数在盲标完成前不展示。

该 Candidate Pool 用于模块分类与 Top-5 排序评测；它不声称穷举了100个资产中的全部相关项。后续严格 Recall@K 评测需要为锁定查询建立较完整的相关参考集合。

## 5. 场景模块验收指标

600 对全部完成后才解锁模型指标，避免标注被分数影响：

- 各人工场景等级的模型分数分布和单调性。
- Graded `NDCG@5`：衡量5个候选的场景排序质量。
- Top-1 人工场景等级。
- `同一/相似工位（等级≥2）`的 Top-1 命中率。
- 困难象限分别统计，重点查看高视觉低文本样本中的场景识别能力。
- 无法判断比例和视频播放失败率。

首轮结果只用于诊断和形成开发基线；阈值调整后必须在未参与调参的锁定集复测。

## 6. 数据切分与防泄漏

开发、校准、锁定测试必须按父视频、人员和场地分组，不能随机拆 Task 导致同一原视频的相邻片段跨集合。四小时先导集主要用于发现问题，不把600对全部当最终测试。

规模扩大后建议：

- 可汇报 MVP：200–300 个库内 Task、300 个查询、约1800个候选 Pair。
- 生产前离线评测：至少1000个库内 Task、500个锁定查询，并由第二标注者抽查10%–20%。

单人标注阶段随机抽10%样本隔一段时间复标，检查自身一致率；标签定义有变化时必须版本化，不能静默覆盖旧真值。

## 7. 实施顺序

1. 保留原50资产/1800查询标注库及已有标签，只读归档。
2. 新建100资产/120查询/600 Pair的统一母测试集和独立数据库。
3. 上线场景盲标页，完成600对场景等级标注。
4. 冻结首版结果，生成场景模块分层报告和错误案例集。
5. 针对人物前景、视角差异和同类工位困难负例优化场景编码与重排。
6. 固定场景模块版本，接入位姿回放并完成同一母集的动作轮。
7. 完成文本轮及描述—视频一致性检查。
8. 完成整体轮，建立可解释规则基线。
9. 扩大样本，按开发/校准/锁定测试训练融合模型并校准概率。
10. 最终接入 Pipeline：版本化特征、模型、阈值和检索结果，增加离线评测与线上回放监控。

## 8. 产物与可追溯要求

- 每次抽样保存 seed、参考/查询/Pair 清单和候选来源。
- 每次模型评测保存编码器版本、权重哈希、抽帧策略和阈值版本。
- 原始标注只追加或版本化，不直接覆盖。
- 错误案例按“场景假阳性、场景假阴性、视角变化、遮挡、描述错误、位姿缺失、部分动作覆盖”归档。
- 线上结果保留三个模块的独立证据和最终理由，不能只保存一个总分。
