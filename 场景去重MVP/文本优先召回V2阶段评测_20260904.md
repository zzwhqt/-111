# 文本优先召回 V2 阶段评测

## 实验设置

- 数据：完成场景标注后的前80个开发查询，每个查询5个已有人工标签候选。
- 人工相关口径：场景等级`>=2`视为相似场景。
- 文本：库内原有`scene + task_name + details`的CLIP文本向量。
- V2全库展示：文本70% + 视觉30%，每个查询重新检索全部100个参考资产。
- 锁定数据：后40个查询不进入本次权重选择。

## 结论

少量加入文本有帮助，但把视觉降为辅助会降低当前“场景相似”指标。开发集最优点为文本20%+视觉80%，相对纯视觉将NDCG@5从0.8442提高到0.8804，Top1等级>=2从27.50%提高到35.00%。文本70%版本仍保留为全库Top-5人工观察实验，不能直接替换正式场景排序。

原因推测：`task_name/details`主要描述人在做什么，容易把“相同动作、不同地点”拉近；它对整个Task重复判断可能重要，但对纯场景重复不应占主导。下一步应拆分`scene`、`task_name`、`details`，分别编码和评测，而不是将三段文本合成一个分数统一加权。

## 边界

上述指标只覆盖原来已标注的5候选。V2页面中的新Top-5来自全部100个资产，其中出现的新候选没有人工标签，必须人工查看或补标后才能计算真正的全库Recall。
